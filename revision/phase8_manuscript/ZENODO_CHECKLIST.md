## Steps for you

1. **[you]** Push the release tag:
   ```bash
   git tag -a v1.0-revision -m "Scientific Reports major revision: multi-seed validation, sensitivity, generalization, attention analysis"
   git push origin v1.0-revision
   ```
2. **[you]** Link the GitHub repository to Zenodo
   (zenodo.org → GitHub → toggle the repository on) **before** creating the
   GitHub Release — Zenodo only captures releases created after linking.
3. **[you]** Create a GitHub Release from the `v1.0-revision` tag. Zenodo will
   archive it automatically and mint a DOI.
4. **[you]** Add the DOI badge to `README.md` and update the Data Availability
   statement with the DOI as above.
5. **[you]** On the Zenodo record, check: title, author list and ORCIDs,
   the MIT licence, and the "related identifier" pointing at the article DOI
   (10.21203/rs.3.rs-9396651/v1 for the preprint).

## One judgement call worth making before archiving

The repository currently carries **~120 MB of experimental data** (339 Phase 1
transition CSVs, 40+ checkpoints, attention traces). That is fine for GitHub and
good for reproducibility, but for the archive you may prefer either:

- **archive as-is** — one DOI, everything self-contained, simplest to cite; or
- **split** — a code-only repository plus a separate Zenodo data deposit, which
  keeps the git history light and gives the dataset its own citable DOI.

For a paper whose central methodological claim is that single-checkpoint
evaluation is unreliable, archiving the full multi-seed data as-is is the more
persuasive option.
