## One judgement call worth making before archiving

The repository currently carries **~120 MB of experimental data** (339 Phase 1
transition CSVs, 40+ checkpoints, attention traces). That is fine for GitHub and
good for reproducibility, but for the archive you may prefer either:

- **archive as-is** — one DOI, everything self-contained, simplest to cite; or
- **split** — a code-only repository plus a separate Zenodo data deposit, which
  keeps the git history light and gives the dataset its own citable DOI.

For a paper whose central methodological claim is that single-checkpoint
evaluation is unreliable, archiving the full multi-seed data as-is is the more
persuasive option.
